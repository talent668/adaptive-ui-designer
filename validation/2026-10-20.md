## Browser evidence

The following summarizes implementer observations and the independent review's inspected subset. Observed Chromium desktop viewport: 1280 × 720. The content panel is separately adjustable; 420/560/760 px are test samples, not required project breakpoints.

- All three scenarios were inspected with English pending-state labels at 420, 560 and 760 px panels. The inventory case also combined `North warehouse` with `Awaiting inventory reconciliation`; at 420 px it used three toolbar rows, with both full values visible. No document-width overflow was observed in these samples. Open menus were inspected separately.
- With matched support content, 760 px used a 41.1 px toolbar; 560 and 420 px used 89.1 px. Short descriptions measured 23.1 px tall. At 760 px the first short/short card row measured 179.8 px, while the mixed row measured 249.1 px. This demonstrates natural text growth and deliberate row alignment, not a before/after performance gain.
- Chinese dark-mode editorial/inventory views, readable dialog surfaces, actual note editing, a 320-character note, canceled editing and empty search were inspected. This is representative coverage, not every locale/theme/content combination.
- Editorial edit: a deliberately rejected local write retained original content and entered text; retry committed the note while retaining the ID filter. Queue processing advanced to the next entity. Inventory batch: two selected records from different categories remained explicitly selected after narrowing to one category; only those two completed, while both non-target records retained their prior state. Reload restored stored notes/completion, not filters or selection.
- Title, details and edit entrances were checked for appropriate focus return. Saving a note that no longer matches the text query returned to search. The independent reviewer tested failed queue/batch writes and direct keyboard retry after the fix below. No console errors were observed in that focused retest.

Two implementer text-entry observations overlapped another agent's IAB input and produced unexpected extra characters. Those entries are not evidence of exact text entry. The agents then serialized browser work; the independent reviewer checked the actual entered values and the DOM regression tests assert exact input. No real-user study or human time saving was measured.

## Independent review and correction

A separate subagent reviewed the changed skill, source, tests, both READMEs and the actual lab. It reproduced one P2 defect: queue completion failure announced an error behind an open modal and lost the retry button's focus. The correction places an alert inside the active dialog or batch region and restores the enabled retry target. A regression test covers both paths.

Independent browser recheck: queue failure kept pending count at four, exposed the modal alert and focused the enabled completion button; Enter retry reduced it to three and focused the next record. Batch failure kept selection/data and focused its retry button; Enter retry changed only the target, leaving the two remaining records unchanged. The defect is resolved in the checked implementation.

The reviewer also performed a source-only forward exercise for a React research retrieval site with subject filters, varied abstracts and a document preview, but no review queue or batch operations. It selected panel-aware labels, natural reading blocks and search/navigation checks, and explicitly excluded unrelated approval, batch and persistence work. This is evidence against obvious scenario overfitting in one exercise, not a completed fourth application.

## Limits retained

- Native CLI discovery and model-application evidence remains the historical 0.3.0 run. Claude model execution remains deferred pending login; OpenCode model execution remains pending credentials. This update does not reclassify them as passed.
- Synthetic fixtures do not replace real business data/API integration. The content lab's session-local workflow handlers are not automatically added to Vue/React/HTML exports; optional structural CSS is included.
- No Safari/Firefox, mobile/tablet, screen-reader session or complete automated visual-regression suite was run. Desktop panel samples and DOM mocks cannot establish those results.
- The new rules are conditional. Grid-row whitespace may be justified, full-width stacking may be appropriate, and a site's subjective score is separate from skill completeness. No target score drove acceptance.
